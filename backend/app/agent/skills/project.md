# Project Skill

## 何时算 project 意图（强动作）

以下类型应走 **项目工具**（须与 `tool_usage.md` 一致）：

- **新建项目 / 创建项目**（明确要建项目实体）  
- **修改项目**（名称、负责人、截止、目标、内需等）  
- **列出 / 查询项目**、项目概况统计  
- **项目状态、里程碑、交付、需求、任务** 等与 **项目实体字段或清单** 直接相关的操作  
- 用户明确说 **给某项目添加进展 / 资源活动** 时，才使用 `add_resource_activity`  

## 何时不是 project 意图

- 句中仅出现 **「项目架构」「项目方案」「项目会议」「商讨项目架构」** 等，若是 **会议主题或会议内容** 描述，应走 **calendar**，**不要**调用项目工具。  
- **不要**仅凭「项目」二字触发 `list_projects` / `create_project`。

## 工具规则

- 新建项目：`create_project` 或 `upsert_project`  
- 修改项目：建议先 `resolve_project`，再 `update_project`  
- **不要猜测 `project_id`**；先用 `resolve_project` 或列表工具确认  
- 新建项目时 **不要**生成 `owner_user_id`；后端使用当前登录用户补全  
- 用户说「负责人是我」：**不要**调用 `resolve_user("我")`；理解为当前登录用户  
- 用户指定其他负责人（如「负责人张三」）：若无法解析，可先创建项目或按 `tool_usage` 追问，避免乱绑  

## `add_resource_activity`

- **仅**在用户 **明确针对某项目** 要追加进展、资源动态、协作记录时使用。  
- **calendar 意图下禁止**；会议类描述不要用此工具替代沟通记录。

## 回复规则

- 执行成功后，回复应包含 **项目名称 / 编号** 与关键变更内容。
