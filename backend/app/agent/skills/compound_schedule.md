# Compound Schedule Skill（复合日程 / 培训行程）

说明 **多天培训、会议行程、主日程 + 子节点 + 本地提醒** 等复合日程语义，及与单次日程工具的关系。

## 能力范围

1. **多天行程**：跨日主日程、日期范围（如「4月8日至9日」与类似中文表达）。  
2. **培训 / 会议 / 集训 / 出差类**安排话术。  
3. **日程 + 本地提醒**：主日程创建成功后，可按规则创建 **每日本地提醒**（`channel=local`），截止不超出主日程结束日。  
4. **明天 / 后天 / 下周** 等相对时间：由系统时间上下文解析；信息不足时应追问或走 `auto_schedule_event` 让后端解析。  
5. **桌面版**仅 **local** 提醒；**不创建**外部渠道推送类提醒。  

## 工具优先级

1. **单日或时间模糊的日常安排**：优先 **`auto_schedule_event`**（传入用户原文 `text` + 合适 `title`）。  
2. **用户已给出明确 ISO 起止**：可用 `create_calendar_event`。  
3. **复合 span + 培训类** 且命中系统 shortcut 时：由 **`execute_compound_schedule` 等价逻辑**（shortcut 内）顺序落库，无需模型再规划。  

## 语义澄清

1. 「会议内容是商讨项目架构」中的「项目」指 **会议主题 / 议程描述**，**不是**项目管理意图；**不要**调用 `list_all_projects`、`create_project`、`add_resource_activity` 等项目工具。  
2. 若 **日期或时间** 不足以创建（解析失败），应 **明确失败或追问补充**，不得口头宣称已创建。  
3. **不要**仅因会议正文出现「项目」「架构」等词就调用 **project** 域工具。  

## 与 shortcut 的关系

当用户输入满足 **复合行程 shortcut** 的启发式条件时，系统可能在 Agent 之前 **直接执行**复合计划；模型在 **fallback Agent** 路径中仍应遵守上述边界，避免幻觉调用项目工具。
