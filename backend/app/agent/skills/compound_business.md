# Compound Business Skill（项目 + 客户 + 沟通）

说明高置信度 **「同时涉及项目与客户，并写入客户沟通」** 的复合业务能力及系统行为。

## 典型例句（系统可优先走确定性 shortcut）

1. 「新建一个项目还有名字叫做H的客户，我和这个客户聊了一下AIweb应用的事情」  
2. 「新建项目，客户叫H，沟通内容是AIweb应用」  
3. 「创建项目并记录客户H的沟通：AIweb应用」  
4. 「新建一个项目，同时新增客户H，记录沟通内容：聊了一下AI web应用」  

## 系统行为（shortcut）

1. 对符合解析规则的复合句，**通常由系统确定性 shortcut 先处理**，**不需要**再走 Ollama 工具规划。  
2. shortcut 命中时 **不调用** `chat` 的 tools 规划循环；直接顺序落库。  
3. **客户**：若同名同主已存在则 **复用**；否则 **创建**。  
4. **项目**：按规则生成默认项目名（与客户名与沟通摘要相关）；若同名同主已存在则 **复用**；否则 **创建**并关联客户。  
5. **沟通**：写入 **`create_customer_interaction`** 等价数据（客户沟通记录），**不是**项目动态，除非用户明确说「给某项目添加进展」类需求。  
6. 若 **客户名** 或 **沟通内容** 无法从原文可靠解析，**不得编造**；应走失败或追问路径（shortcut 未命中时由 Agent 工具路径处理）。  
7. **部分成功**（例如客户创建成功但项目失败）必须在回复中 **逐步说明** 哪一步成功、哪一步失败（见 `reply_rules` / `diagnostics`）。  
8. **不调用**外部 IM 或第三方协作 API；不依赖外部身份。  
9. **不依赖切换视角**；一律当前登录用户。  
10. **不要把客户沟通误写成 `add_resource_activity`（项目资源活动）**，除非用户明确针对某项目要进展记录。

## 与 Agent fallback 的关系

若 shortcut **未命中**（句式不符合解析器），则回退到 **customer / project** 等常规 intent 与 tools；此时你仍应遵守 `tool_usage.md` 与 `customer.md`，分步调用合适工具完成任务。
